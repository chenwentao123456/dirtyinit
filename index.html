        01 — 简介
        
它不是 Root，是「临时拿到 init 域」

      

      

        

          

            DirtyInit 走的是页缓存（page cache）篡改路线：通过 IpSecManager 相关接口在目标
            libbase.so 上完成一次可控的 16 字节块写，把本应只读的代码页改成我们需要的跳转，
            从而在 init 上下文中获得一次代码执行的机会。
          

          

            执行成功后，APK 会把一个 dirtyinit ELF 投放到 /data/local/tmp/，
            再借由 relay payload 打开一条 init 域的 shell 通道；你在 Termux 里得到的
            uid=0 会话，安全上下文是 u:r:init:s0 —— 比普通 root 更"靠前"的一层。
          

          

            因为整个过程只在内存与页缓存里发生，不写 /system、不动分区、不解锁 BL、不刷 boot，
            设备重启即完全还原。这也是它无法（也不需要）做成常驻 root 的原因。
          

          

            注意
            页缓存状态是「一次性」的：同一次开机内只允许干净部署一种 payload，混用可能读到被改过的字节，导致 kernel panic。
          

        

        

          

            
01

            
页缓存写入

            
目标 ELF 的只读代码页被映射改写，得到一个很小的代码执行窗口。

          

          

            
02

            
relay init shell

            
把 dirtyinit ELF 落到 /data/local/tmp，打开 init 域通道。

          

          

            
03

            
运行时、可逆

            
全部改动只在内存与运行时属性里，重启还原；调优脚本支持 restore。

          

        

      

    

  


  
  

    

      

        02 — 功能
        
一个 APK，三套武器

        
提权入口、ADB 通道、硬件调优，全部收在一个面板里。

      

      

        

          

            
          

          
一键提权（EXECUTE EXPLOIT）

          
点一下就完成 payload 注入与 relay 部署，成功后可直接 EXTRACT CLI 到 Termux，用 dirtyinit / rish 操作 init 域。

          
  • init shell
  • u:r:init:s0
  • ELF 落地

        


        

          

            
          

          
一键开启 ADB 5555

          
自动 setprop service.adb.tcp.port 5555 并 ctl.restart adbd，15–20 秒后手机开始监听 TCP 5555，电脑直接 adb connect。

          
  • adbd 重启
  • [::]:5555
  • 免数据线

        


        

          

            
          

          
二合一 payload

          
ENABLE ADB 5555 按钮内部自动分两阶段：先注入 ADB payload，再用「直接返回」版 relay payload 收尾，避免破坏第一次部署。

          
  • 两阶段注入
  • 同一开机内安全
  • ~20s

        


        

          

            
          

          
硬件调优面板（tools3）

          
CPU 三簇频率锁定、schedutil 升频曲线、温控守护进程开关、内存 VM 参数与触控响应，全部图形化操作。

          
  • CPU max
  • thermal stop
  • mem opt

        


        

          

            
          

          
无界面触发

          
脚本、快捷指令、锁屏自动化都能用 am start … --ez autorun true 直接触发，等价于点按钮，适合自动化流水线。

          
  • am start
  • autorun
  • 可脚本化

        


        

          

            
          

          
可撤销，不脏系统

          
调优脚本每个动作都会备份原值，restore 一键回滚；APK 侧的所有改动随重启消失，不给系统留垃圾。

          
  • restore
  • 无残留
  • 重启还原

        

      

    

  


  
  

    

      

        03 — 流程
        
三步，从安装到 init shell

        
以下命令可直接复制，替换 <手机IP> 即可。

      


      

        

          
STEP 1

          
安装 APK

          
修改版使用 debug 签名，与官方原版不同，安装前先卸载原版 com.dirty.init（会丢原 App 数据，sdcard 文件不受影响）。

          

            
            
# 卸载原版后安装修改版
adb install -r dirtyinit_tools3.apk

          

        


        

          
STEP 2

          
触发部署

          
点亮并解锁屏幕，打开 App 点 ENABLE ADB 5555（或 ONE-TOUCH EXPLOIT），也可以用命令无界面触发。安全锁屏状态下 Activity 会被延迟启动。

          

            
            
# 等价于点击按钮
adb shell am start -n com.dirty.init/.DirtyInitActivity \
  --ez autorun true

          

        


        

          
STEP 3

          
连接并验证

          
手机与电脑同一局域网，确认 5555 已监听后 adb connect，再验证 relay 的 uid 与安全上下文。

          

            
            
adb shell getprop service.adb.tcp.port   # 5555
adb shell netstat -tln | grep 5555       # [::]:5555 LISTEN
adb connect <手机IP>:5555               # connected to ...
adb shell /data/local/tmp/dirtyinit id   # uid=0(root) context=u:r:init:s0

          

        

      


      

        
!

        

          
同一次开机内只能干净部署一种 payload

          
先 EXECUTE EXPLOIT 再点 ENABLE ADB 5555（或反过来）可能读到被改过的 libbase 字节，触发 kernel panic。要换模式请先重启手机。

        06 — 常见问题
        
动手前先看这几条

      

      

        

          需要先 root 吗？
          
不需要。DirtyInit 自己就是提权入口：它依赖的是本机 libbase.so 的页缓存写入原语，而不是一个已有的 su。但它要求屏幕处于解锁状态，安全锁屏下 Activity 会被系统延迟启动（am start 返回 -92）。

        

        

          为什么重启后 ADB 5555 就没了？
          
service.adb.tcp.port 是运行时属性，写在内存里的 init 属性区，重启即丢；5555 的监听也随 adbd 重启而消失。每次开机后重新点一次 ENABLE ADB 5555（或用 am start … autorun true）即可。

        

        

          同一次开机为什么不能换 payload？
          
页缓存的改动是「写进去就一直脏着」的：第二次部署时如果读到上一次被改过的 libbase 字节，relay 的构造会失效，最坏情况是 kernel panic。换模式请先重启手机，让页缓存恢复干净。

        

        

          安装时报签名冲突 / 覆盖失败？
          
修改版使用 debug 签名，与官方原版不同。先卸载 com.dirty.init 再安装（会丢原 App 数据，/sdcard 上的文件不受影响）。

        

        

          为什么不能上 KernelSU？
          
这台机器的内核开了 CONFIG_MODULE_SIG_FORCE=y，模块只能用华为私钥签名，加上 MODVERSIONS=y、BL 锁定与 verity，未签名或第三方编译的 .ko 无法加载，所以 ko 路线走不通。

        

        

          风险大吗？会不会变砖？
          
它对系统的持久改动为零：不写 /system、不改分区、不解锁 BL。但页缓存操作本身属于不稳定原语，重复/混用 payload 可能导致内核 panic（重启即可恢复）。beast 会关闭温控，长时间满载有发热与电池损耗风险，随时 restore 回滚。

        

        

          可以拿去做别的事吗？
          
不可以。本项目仅供自有设备的本地研究、测试与调优；请勿用于任何未授权设备。使用即表示你理解并自行承担全部风险。
